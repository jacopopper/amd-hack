### Review follow-up: room scale, empty rooms and failed stages

The three reported bugs are corrected. The updated CPU/API suite passes **74 tests in 8.66 seconds**; Python compilation and `git diff --check` pass. No additional GPU or external-service run was performed for this follow-up.

- **Common room coordinates:** new links explicitly require `coordinate_space: metric_scene_coordinates` and `residual_unit: m`. Both endpoint scenes need valid metric calibration metadata. `transform_from_to` is rigid in those already scaled coordinates: `p_to_m = R @ (scale_from * p_from_raw) + t_m`. Each placement maps raw scene coordinates directly to the reference component using `T_scene_to_reference_metric @ diag(scale_scene, scale_scene, scale_scene, 1)`. The reference room is scaled too. Placements declare their units, reference scene and applied scale; do not apply scale or individual display transforms again.
- **No inferred shared scale:** an uncalibrated scene remains an independent relative component. The API rejects new links without valid endpoint calibrations (409), or without the explicit metric coordinate contract (422). Stored legacy links remain readable with `state: requires_metric_review`, but do not connect the house. Links bind the calibration IDs and scale factors confirmed by the reviewer; recalibration makes them `calibration_changed`, and removing calibration makes them `scale_unavailable`. They require explicit reconfirmation. Tests cover scales 1 and 2, three-room rotation/translation with unequal scales, and calibration changes/removal.
- **Current versus historical rooms:** bundle, scene routes, room-link resolution and worker input use only rooms with active photos. Removing the last photo hides that room without deleting historical photo/scene rows; a later upload can reactivate its original room ID. Photo edits invalidate only the affected scene and its incident links/measurements, preserving independent ready rooms.
- **Failure diagnosis:** completed independent stages no longer replace the failed job's final `stage`. A Gemma failure followed by a successful avatar ends with `stage: gemma`; multiple failures retain the first actual failure in pipeline order. `/api/jobs/{id}` also returns `failed_stages`; blocked dependent stages are not reported as failures.

The earlier real single-image CUDA/MPFB draft evidence remains historical local-runtime evidence, separate from the later four-screenshot live run. A real guided capture and connected-room validation remain open.
